# Архитектура и RAG

## Путь данных

Overpass → исходный JSON → нормализация и валидация → версионированный `data/poi.json` → SQLite/FTS5 и матрица multilingual MiniLM → FastAPI → React/Leaflet.

Начальная точка и параметры поступают только в POST. Географический фильтр и жёсткие ограничения оставляют допустимые POI. Поиск объединяет top-30 FTS5 и top-30 cosine similarity через Reciprocal Rank Fusion. Итоговый рейтинг учитывает явно выбранные интересы, поиск и близость. Ни один поисковый балл не отменяет жёсткий фильтр.

Embedding-документ включает название, языковые варианты, категорию, описание и полезные исходные теги. Используется `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` через FastEmbed/ONNX, 384 измерения. Модель загружается только при явной подготовке индекса; сервер при запуске использует локальный кеш. Если его нет, UI раскрывает `lexical` fallback. Матрица содержит хеш модели и текста; подмена или смена модели приводит к новому индексу.

## Генерация

Режим без ключа: факты и мотивировка из проверенных полей плюс шаблонная идея. Это демо поиска и проверки ограничений.

Режим Gemini: найденные места, их evidence IDs, категории и нормализованные предпочтения → JSON Schema → порядок мест и ключи подходящих занятий → проверка ID, полноты, уникальности, источников и категории → текст из проверенного словаря. Две попытки ограничены общим таймаутом 18 секунд. Некорректный ответ не заменяет корректные шаблонные результаты.

Таким образом, live RAG действительно опирается на retrieved context; генеративная свобода намеренно ограничена. Модель не рассчитывает расстояния, не утверждает часы работы, не создаёт события и не придумывает места. Расширение до свободных объяснений требует отдельной оценки фактической достоверности.

## Контракт времени

Часовой пояс: `Asia/Almaty` из tzdata. Входной `starts_at` должен включать offset. Пешеходная оценка: `ceil(distance_km / 4.5 × 60 × 1.3)`, минимум одна минута. Это не расчёт по дорогам. Длительность посещения — фиксированная оценка по категории. При включённом возврате учитываются две ноги пути. Каждая рекомендация — отдельный вариант, а не последовательный маршрут.

Проверяется открытость на протяжении всего посещения. Поддерживаются 24/7, интервалы дней недели, обычные часы, несколько дневных интервалов и переход через полночь. Сложные конструкции, праздничные исключения, отсутствие данных и снимок старше 180 дней дают unknown. Известно закрытые места исключаются. Unknown исключается при строгом фильтре открытости.

## Надёжность и обновления

Сборщик ограничивает повторы, использует задержки и резервный endpoint; неполный ответ с `remark` отклоняется. Запись снимка атомарная. `refresh` строит индекс на staged-снимке до его публикации. Сервер удерживает согласованную версию данных и индекса до перезапуска. SQLite производная и восстанавливается из снимка; индекс версии не перезаписывает индекс другой версии.

На клиенте предыдущий запрос отменяется; запоздалый ответ не может заменить актуальный. Изменение параметров во время запроса сохраняет предупреждение о необходимости обновления. Проблемы карты не блокируют список. ResizeObserver пересчитывает Leaflet при переключении мобильных вкладок.

## API

- `GET /api/health`: процесс жив.
- `GET /api/ready`: есть данные, режим поиска, наличие конфигурации LLM.
- `GET /api/dataset/status`: версия, категории, размер, дата, атрибуция.
- `GET /api/poi/{id}`: объект с происхождением полей.
- `POST /api/recommendations`: локация, запрос, время, радиус, фильтры → рекомендации, ограничения, режимы, предупреждения.

OpenAPI доступен на `/docs`. Для публичного запуска нужны HTTPS, ограничения ресурсов и соответствующая политика reverse-proxy; localhost-конфигурация не является масштабируемым production-развёртыванием.
